Variables

A beginner-friendly guide to declaring, assigning, and using variables with var, let, and const.

1. What is a variable?

A variable is a named place in a program that lets us store a value and use it later.

Analogy: Think of a variable as a labelled box. The label is the variable name, and the value is what you keep inside the box.
let age = 20;
console.log(age); // 20
  • let — keyword used to declare the variable.
  • age — variable name (identifier).
  • = — assignment operator; it assigns the value on the right to the variable on the left.
  • 20 — value stored in the variable.
  • ; — ends the statement. JavaScript can insert semicolons automatically in many cases, but writing them consistently is a good habit.

2. Declaration, initialization, and reassignment

let score;       // Declaration: create the variable
score = 10;      // Assignment: give it a value
score = 15;      // Reassignment: change its value
console.log(score); // 15

Initialization means giving a variable its first value, usually while declaring it:

let score = 10;  // Declaration + initialization
A variable declared with let but not yet assigned a value contains undefined. A const variable must receive a value when it is declared.

3. The three variable keywords

KeywordCan reassign?Can redeclare in the same scope?ScopeGuidance
varYesYesFunction scope (or global scope)Older JavaScript; understand it, but avoid it in most modern code.
letYesNoBlock scopeUse when the variable's value needs to change.
constNo (binding cannot be reassigned)NoBlock scopePrefer by default when you will not reassign the variable.

Historical note: var existed in older JavaScript. let and const were introduced in ECMAScript 2015 (ES6).

Example A — let

let number = 10;
number = 45;              // Allowed: reassignment
console.log(number);      // 45

// let number = 50;       // Error in the same scope: redeclaration

Example B — var

var amount = 10;
amount = 100;             // Allowed: reassignment
var amount = 200;         // Allowed, but often confusing
console.log(amount);      // 200

Example C — const

const taxRate = 0.18;
console.log(taxRate);     // 0.18

// taxRate = 0.20;        // TypeError: cannot reassign a const
// const taxRate = 0.25;  // SyntaxError: redeclaration in same scope
// const city;            // SyntaxError: const needs an initial value
Important detail: const prevents reassignment of the variable binding. If it refers to an object or array, the object's contents can still be changed; the variable cannot be pointed to a different object.
const colors = ["red", "blue"];
colors.push("green");       // Allowed: modifies the array
// colors = ["black"];      // Not allowed: reassigns the variable
console.log(colors);

4. Your class example — corrected and explained

JavaScript does not require a main() function. You can create one yourself and call it, as shown here.

function main() {
  let n;
  n = 10;
  console.log(n); // 10

  var a;
  a = 45;
  console.log(a); // 45

  const b = 15;
  console.log(b); // 15
}

main();

The three outputs appear on separate lines: 10, 45, and 15.

When running JavaScript in a browser, open Developer Tools → Console to see console.log() output. In this page, the buttons below also show sample output directly.

5. Redeclaration vs reassignment

ActionMeaningExample
DeclarationCreate a variable binding.let count;
InitializationGive it its first value.let count = 1;
ReassignmentGive an existing variable a new value.count = 2;
RedeclarationDeclare the same name again in the same scope.let count = 1; let count = 2; — error
 
// let: reassignment is okay
let n1 = 12;
n1 = 30;
console.log(n1); // 30

// let: redeclaration in the same scope is not okay
// let n1 = 40; // SyntaxError
Remember: let = reassign allowed, same-scope redeclaration not allowed.

6. Why not create a variable without a keyword?

In non-strict, older-style JavaScript, assigning to an undeclared name may accidentally create a global variable. This is a bug-prone practice and should be avoided.

function main() {
  "use strict";
  // x = 12; // ReferenceError: x was never declared
  let x = 12;
  console.log(x);
}
main();
Strict mode: "use strict"; makes assigning to an undeclared variable an error. Put the directive at the beginning of a script or function. Modern JavaScript modules are strict by default.

Best practice: always declare variables with const or let. Use var mainly when reading older code or when a specific legacy requirement calls for it.

7. Scope: where can a variable be used?

Scope means the part of the program where a variable is accessible.

Block scope: let and const

if (true) {
  let message = "Hello";
  const year = 2026;
  console.log(message); // Hello
}
// console.log(message); // ReferenceError: outside its block

var is not block-scoped

if (true) {
  var oldStyle = "I can be accessed outside this block";
}
console.log(oldStyle); // Works (in this example)

A function still creates a scope for var. This difference is one reason let and const are safer for everyday code.

8. Variable naming rules

  • Names can contain letters, digits, _, and $.
  • A name cannot start with a digit.
  • Names cannot be reserved keywords such as let, const, or if.
  • JavaScript is case-sensitive: age, Age, and AGE are different names.
  • Use descriptive names and usually camelCase: studentName, totalPrice, isLoggedIn.
let studentName = "Asha"; // Good
let totalMarks = 450;     // Good
// let 2marks = 20;        // Invalid: starts with a digit
// let let = 5;            // Invalid: reserved keyword
let user_name = "Ravi";   // Valid, though camelCase is common in JS

9. JavaScript is dynamically typed

You do not write a data type such as int when declaring a normal JavaScript variable. The value has a type, and a let variable can later hold a value of another type.

let value = 10;
console.log(typeof value); // "number"

value = "ten";
console.log(typeof value); // "string"

Common primitive value types include number, string, boolean, undefined, bigint, symbol, and null (with a historical quirk: typeof null returns "object").

11. Common mistakes to avoid

  • Using const without an initial value.
  • Trying to redeclare a let or const name in the same scope.
  • Trying to reassign a const variable.
  • Forgetting that names are case-sensitive.
  • Assigning to a variable before declaring it.
  • Assuming const makes an array or object completely immutable.
  • Using var without understanding its function scope and redeclaration behavior.

13. Quick revision checklist

Interview-ready summary: Prefer const when you do not need to reassign a variable and let when you do. Both are block-scoped and cannot be redeclared in the same scope. var is function-scoped and permits redeclaration. Always declare variables explicitly.
